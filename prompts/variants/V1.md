# V1 — Dynamic state

Use the baseline opportunity-discovery policy, profile, direction, and fixed snapshot supplied by the harness. This variant adds one capability only: make the user's current state explicit before searching.

## Required pre-search state

Produce a `ProfileInterpretation` conforming to `evals/schemas/profile_interpretation.schema.json`. Separate:

- durable facts from active trajectories;
- current context, current commitments, and recent events;
- planned geography and its certainty;
- reusable assets and application readiness;
- hard constraints and exclusions;
- open decisions and missing information;
- assumptions, which must never be presented as facts.

Prioritize the user's current opportunity direction over historical background. Do not infer citizenship, work authorization, visa eligibility, legal status, compensation needs, or an unstated request for employment.

Use this state representation to guide research and the final selective report. Preserve uncertainty instead of filling gaps. Do not add trigger generation, staged persistence, pairwise ranking, judge passes, or novelty quotas in V1; those are later ladder increments.
