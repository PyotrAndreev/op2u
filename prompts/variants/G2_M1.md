# G2_M1 — Strict ACT_NOW gate plus conservative selected-week budget

Parent: `G1_M3`
Affected stage: `ranking` only

Apply V1–V4 and the complete G1_M3 strict ACT_NOW behavior unchanged. ACT_NOW still requires: (1) exact official quote, URL, and retrieval time proving a currently live actionable state; (2) a source-backed specific `why_now`; and (3) one atomic tangible first action, startable without unresolved eligibility assumptions, taking at most 60 minutes.

## Exactly one mutation: conservative selected-week budget allocation

At ranking, distinguish three effort concepts explicitly for every retained candidate:

- `first_action_minutes`: the atomic first step;
- `scheduled_this_week_minutes`: all work the report actually asks the user to do in the next seven days;
- `total_completion_effort_hours`: informational full-funnel effort, which is not scheduled unless explicitly selected.

Normalize `scheduled_this_week_minutes` to a closed integer range. Sum the **upper bounds** for every ACT_NOW and PREPARE_NEXT/MONITOR action the report asks the user to perform this week. The selected weekly portfolio is valid only when this conservative upper-bound total is at most 360 minutes. If it exceeds 360, defer, downgrade, or remove weekly actions until it passes; do not say “choose one” while retaining all actions as selected.

Persist a `weekly_action_budget` object with the 360-minute cap, each selected action reference and range, lower and upper totals, unused upper-bound budget, and PASS/FAIL. Preserve `total_completion_effort_hours` separately so judges cannot mistake it for scheduled weekly effort. The report must copy this exact allocation, label all unscheduled candidates as deferred with **no action requested this week**, and must not claim compliance from lower bounds or first actions alone.

Do not change discovery, verification, actionability generation, evidence rules, or the G1_M3 liveness gate. This mutation only makes ranking and final portfolio scheduling conservatively budget-safe.
