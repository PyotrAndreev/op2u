# G1_M1 — Conservative action-budget allocation

Parent: `V4`
Affected stage: `ranking` only

Apply V1–V4 in full. The behavior below is unchanged:

- **V1:** Make the user's dynamic state explicit before search. Separate durable facts, active trajectories, context, commitments, events, geography certainty, reusable assets, readiness, constraints, exclusions, open decisions, missing information, and assumptions. Never infer citizenship, work authorization, visa eligibility, legal status, compensation needs, or an unstated employment request; preserve uncertainty.
- **V2:** Produce non-empty context-trigger hypotheses connecting at least two independent profile signals. Use them as search directions alongside direct categories, while keeping triggers distinct from evidence and preserving all V1 exclusions.
- **V3:** For every serious candidate, preserve the causal bridge, assets, blockers, uncertainty, effort, internal deadline, fallback, and an atomic verb-led seven-day deliverable with a plausible minute estimate. `ACT_NOW` still requires a concrete bridge, verified current status, sufficient official evidence, and an executable first action; otherwise use `PREPARE_NEXT`, `MONITOR`, or `EXCLUDE`. Keep baseline job exclusion, selectivity, and the six-hour weekly effort gate.
- **V4:** Run the named persisted stages in order: `profile_interpretation`, `trigger_synthesis`, `search_plan`, `discovery`, `verification`, `actionability`, `ranking`, and `report`. Save each machine-readable artifact before using it, pass later stages only declared artifact references and content hashes, use only persisted facts in the final report, label inference/assumptions/unknowns, and preserve failed or partial stages. Keep all V1–V3 gates. Do not add pairwise ranking, judge-specific evaluation, or a serendipity reservation.

## Exactly one mutation: allocate the shared action budget conservatively

Change only the `ranking` stage. Do not change discovery, verification, actionability definitions, report evidence rules, or any other V1–V4 behavior.

At ranking time, turn every candidate's proposed first action effort into a closed integer-minute range `[lower_minutes, upper_minutes]`. A point estimate becomes `[point, point]`; a range remains a range; an unbounded or vague estimate must be conservatively bounded from the saved actionability artifact or the candidate must not be selected. Never use the midpoint or lower bound to pass the budget gate.

Select a portfolio by explicitly allocating the shared weekly action budget:

- Treat every action explicitly recommended for the current seven-day period as consuming budget, including selected `ACT_NOW` and `PREPARE_NEXT` actions. Clearly deferred later work is not part of this week's allocation.
- Sum both bounds across the selected set and require the conservative upper-bound total to be `<= 360` minutes. The lower and upper totals, selected action references, and unused budget must be saved in the `ranking` artifact.
- If the upper-bound total exceeds 360 minutes, remove or downgrade candidates and rerank using the existing V3/V4 dimensions, penalties, diversity decisions, and exclusions. Do not merely advise the user to choose a subset while leaving the over-budget set selected.
- Preserve excluded and downgraded candidates with the reason, and do not invent precision. A budget-feasible smaller set is preferable to an ambiguous or over-budget shortlist.

The report must reflect the saved allocation and may not claim that the selected actions fit the cap unless the persisted upper-bound sum proves it. No new stage or schema is added; this is a conservative aggregation and allocation rule inside `ranking` only.
